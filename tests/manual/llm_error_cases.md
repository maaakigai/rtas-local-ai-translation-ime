# LLM エラーケース検証メモ

## 1. ネットワーク未起動
- 条件: Ollama サーバーを停止した状態で翻訳レイヤーを起動。
- 期待結果:
  - プレースホルダ表示後、数秒で消滅し既存候補へ復帰。
  - UI 上でエラー文言を表示しない（静かにフォールバック）。
  - デバッグファイルログを明示的に有効化した場合だけ、設定先にタイムアウト情報が残る。

## 2. 400 番台レスポンス
- 条件: `IME3_OLLAMA_MODEL` に存在しないモデル名を設定。
- 期待結果:
  - 翻訳候補は追加されない。
  - デバッグログを明示的に有効化した場合、`HTTP 404`相当のエラー情報が残る。

## 3. 空応答
- 条件: プロンプトを `APPEND_MODE=ON` のみで構成し、翻訳テキストが空になるように改変。
- 期待結果:
  - キャッシュは更新されず、既存候補へ戻る。
  - Space 巡回で既存キャッシュが維持される。

## 4. キャンセル競合
- 条件: 翻訳待ち状態で `Esc` を押して候補を閉じ、直後に別の文で候補を開く。
- 期待結果:
  - 先行ジョブはキャンセルされる。
  - 新しい候補には影響せず、プレースホルダが正しく表示される。

## 5. 任意のデバッグログ上限
- 条件: `provider.logging.debug_file.enabled=true`として、上限を小さく設定して連続操作する。
- 期待結果:
  - 設定した`max_bytes`付近でログがローテーションされる。
  - 入力本文と生成本文がログに含まれないことを確認する。
