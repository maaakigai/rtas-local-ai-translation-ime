# 正規化ルール（LLM 応答）

Layer2/Layer3 の LLM 応答を候補へ変換する際に適用する正規化ルールを以下にまとめる。

1. **前後トリム**  
   - 全角/半角スペース、タブ、改行を含む空白を削除。
   - `TrimWhitespace` 実装を共通利用。

2. **改行正規化**  
   - `\r\n`/`\r` を `\n` に統一。
   - タブは半角スペースへ変換。

3. **全角スペース変換**  
   - U+3000（IDEOGRAPHIC SPACE）は半角スペースに変換。

4. **Layer2 固有処理**  
   - JSON 配列 (`[ {...}, {...} ]`) を想定。各オブジェクトの `variant` を正規化。
   - `delta=suffix` かつ base 文が含まれない場合は `commitText = base + variant` とし、 `metadata.partial=true` をセット。
   - `tone`/`delta` はメタデータへ格納し UI バッジで利用できるようにする。

5. **Layer3 固有処理**  
   - 応答先頭が `APPEND_MODE=ON`（大文字小文字無視）の場合はフラグを立て、残りテキストを正規化したうえで commit モードを `append` に変更。
   - 正規化後テキストが空になった場合はエラーとして扱う。

6. **共通エラー判定**  
   - 正規化後の文字数が 0 の場合、`ParseResult.error` に理由を格納して TextService 側でフォールバック処理を行う。
   - JSON 構造不正（括弧の不均衡など）はメッセージを返し、再問い合わせ決定の材料とする。

これらのルールは `src/llm/llm_response_parser.cpp` に実装され、追加の正規化要件が生じた場合は本ドキュメントと実装を同時に更新する。
