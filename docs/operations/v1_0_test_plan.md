# RTAS IME V1.0 テスト要項

## 1. 目的
- V1.0 リリース可否を判断するため、主要機能の動作・回帰・実用性を確認する。

## 2. 判定基準（V1.0 合格）
- `Critical` 0件（入力不能、確定不能、文字消失、アプリクラッシュ）
- `High` 0件（主要フローで誤変換が継続発生、操作不能）
- テストケース実行完了率 100%
- 必須ケース（`P0`）合格率 100%

## 3. テスト環境
- OS: Windows 10/11（日本語キーボード JIS）
- ビルド: `Debug|x64` または `Release|x64`
- IME設定: `config/ime_settings.json` の `provider.kana.mode = mozc`
- 対象アプリ:
  - メモ帳（Notepad）
  - VS Code または同等エディタ
  - ブラウザのテキスト入力欄

## 4. 事前準備
- RTAS IME を登録し、入力切替可能であることを確認。
- 競合する独自キーソフトを停止。
- テスト中は同一手順を2回以上実施し、再現性を確認。

## 5. テスト観点
- 基本入力（かな化、記号、数字、Backspace）
- 変換操作（Space/Enter、候補選択、再変換）
- 状態遷移（青下線/オレンジ下線、継続入力）
- 文節操作（左右キーで対象節移動）
- 学習挙動（確定頻度による順位上昇）
- Mozc互換性（候補の妥当性、不自然な重複変換の抑止）
- 永続化（アンインストール相当後の学習データ残存）

## 6. 重点シナリオ（P0）

### P0-01 基本かな入力
- 手順:
  1. `nya nyu nyo` を入力する
  2. `Space` を押して候補表示
- 期待:
  - `んやんゆんよ` ではなく意図した読みで候補化される
  - 候補UI表示中に操作不能にならない

### P0-02 青下線での Backspace
- 手順:
  1. `あ` を入力（青下線）
  2. `Backspace` を1回押す
- 期待:
  - 1回で文字が削除される（青下線解除だけで終わらない）

### P0-03 変換中キャンセル
- 手順:
  1. 文字列入力後 `Space` で変換開始
  2. `Backspace` 1回
- 期待:
  - 変換候補が閉じる
  - 文字が不要に1文字消えない

### P0-04 オレンジ→青遷移後の Enter
- 手順:
  1. `長文って打ってると` 入力
  2. `Enter`（オレンジ下線）
  3. 続けて `なんか` 入力（青下線）
  4. `Backspace` で `なん` にする
  5. `Enter`
- 期待:
  - `長文何なん` のような重複/破綻変換にならない
  - 入力全体が消失しない

### P0-05 オレンジ→青遷移後の Space
- 手順:
  1. P0-04 と同様に `...なん` まで入力
  2. `Space`
- 期待:
  - `...南下なん` のような異常変換をしない
  - 候補UIが固まらない

### P0-06 文節移動
- 手順:
  1. 文節を含む文章を入力し `Space`
  2. `Left/Right` で変換対象節を切替
- 期待:
  - 対象節が移動する
  - プレエディットが崩れない

### P0-07 長文候補の保持
- 手順:
  1. `ちょうぶんうってると` を入力し `Space`
  2. 候補選択を複数回切替
- 期待:
  - `長文` 系候補が消えない
  - プレビューが短い語だけに潰れない

### P0-08 連続確定
- 手順:
  1. 文章を入力して `Enter` 確定
  2. そのまま次文を入力し再度 `Enter`
- 期待:
  - 前文が再変換されない
  - 文字化け/重複確定しない

## 7. 回帰テスト（P1）

### P1-01 記号入力
- 手順: `Shift + ・` 含む主要記号を入力
- 期待: 文字が欠落しない

### P1-02 数字入力
- 手順: `0-9` と `Shift+数字` を入力
- 期待: プレエディット/確定が期待通り

### P1-03 候補順位学習
- 手順:
  1. 同じ読みで同一候補を5回確定
  2. 再度同じ読みで `Space`
- 期待:
  - 学習候補が上位化される

### P1-04 学習データ永続化
- 手順:
  1. 学習後、再起動（または再登録）
  2. 同読みで候補確認
- 期待:
  - 学習結果が保持される
  - 保存先: `%APPDATA%\\RTAS\\user_data\\candidate_usage.tsv`

### P1-05 候補UI起動直後選択
- 手順: 候補UIを開き初期選択を確認
- 期待: 先頭候補から開始する

### P1-06 キャレット左右移動（変換中）
- 手順: オレンジ下線中に `Left/Right`
- 期待:
  - プレエディットを維持したままキャレット移動できる
  - 予期せぬ確定が起きない

## 8. Mozc整合性チェック（P1）
- 入力語例:
  - `ねこ`
  - `おげんきですか`
  - `ちょうぶん`
  - `へんかんなんか`
- 観点:
  - 候補順が極端に不自然でない
  - 絵文字が常に先頭になる等の致命的不便がない
  - 文節区切りで実用上の破綻がない

## 10. 不具合優先度
- `Critical`: 入力不能、確定不能、文字消失、クラッシュ
- `High`: 継続利用困難な誤動作（重複変換、再現率高）
- `Medium`: 回避策ありの誤動作
- `Low`: 表示揺れ、文言、軽微な体感差

## 11. 出荷判定フロー
- 1. `P0` 全件 `Pass`
- 2. `Critical/High` が 0 件
- 3. `P1` の未解決はリスク記載の上で承認判断
- 4. リリースノートに既知制限を明記
